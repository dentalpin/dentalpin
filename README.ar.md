## لماذا DentalPin؟

تتشارك عيادات الأسنان حول العالم في نفس الاحتياجات الأساسية: إدارة المرضى، جدولة المواعيد، تتبع العلاجات، وإدارة العيادة بفعالية. ومع ذلك، فإن مشهد البرمجيات الحالي مجزأ إلى عشرات الحلول المحلية والمغلقة المصدر التي تقيد العيادات بعقود مكلفة وتقنيات قديمة.

**نحن نؤمن بأن الوقت قد حان للتغيير.**

تأسس DentalPin على فرضية بسيطة: **منصة مفتوحة واحدة لعيادات الأسنان في كل مكان**. ليس حلاً إقليمياً آخر، بل أساساً عالمياً يمكن لأي عيادة اعتماده، ولأي مطور توسيعه، ولأي مجتمع تعريبه وتوطينه.

### لماذا الآن؟

لقد غيّر الذكاء الاصطناعي بشكل جذري ما يمكن للفرق الصغيرة بناؤه. الميزات التي كانت تتطلب في السابق أقسام تطوير كبيرة يمكن الآن تنفيذها في أيام. هذه هي فرصتنا لإنشاء برنامج أسنان مفتوح المصدر كان يجب أن يكون موجوداً منذ سنوات — قبل أن تُحاصر العيادات في أنظمة قديمة لا يمكنها الهروب منها.

### مبادئنا

- **مفتوح المصدر** — بيانات عيادتك ملك لك. ويجب أن يكون برنامجك كذلك أيضاً.
- **معياري (Modular)** — ابدأ ببساطة، وأضف ما تحتاجه. لا تدفع مقابل ميزات لن تستخدمها أبداً.
- **عالمي بالتصميم** — مصمم للتوطين والتعريب منذ اليوم الأول. نفس النواة، بأي لغة، في أي بلد.
- **واجهة برمجة التطبيقات أولاً (API-First)** — كل ميزة هي واجهة برمجة تطبيقات (API). تكامل مع أي شيء، وأتمت كل شيء.
- **جاهز للذكاء الاصطناعي (AI-Ready)** — مهيكل لعصر الذكاء الاصطناعي. جاهز للجدولة الذكية، ودعم القرار السريري، وأتمتة سير العمل.

### الرؤية

نحن لا نبني مجرد برنامج — نحن نبني الأساس لنظام بيئي. منصة يساهم فيها المطورون بالوحدات (modules)، وتتشارك العيادات التحسينات، ويستفيد مجتمع طب الأسنان بأكمله من الابتكار الجماعي.

تستحق العيادات ما هو أفضل من البرمجيات المغلقة والمكلفة من العقد الماضي. DentalPin هو البديل المفتوح.

## ✨ مساعد الذكاء الاصطناعي (AI Copilot)

يأتي DentalPin مزوداً بـ **مساعد ذكاء اصطناعي تفاعلي (agentic AI assistant)** مدمج يحول العيادة بأكملها إلى شيء يمكنك ببساطة التحدث إليه. اطلب منه البحث عن مريض، تفريغ خانة موعد، متابعة ميزانية معلقة، أو إعطائك ملخصاً لليوم المقبل — باللغتين العربية أو الإنجليزية — وسيقوم بالعمل على بياناتك الفعلية.

![AI Copilot](docs/screenshots/ia.png)

هذا ليس مجرد روبوت محادثة (chatbot) مضاف بشكل عابر. المساعد (Copilot) هو وكيل حقيقي **يخطط وينفذ مهام متعددة الخطوات** من خلال استدعاء نفس العمليات التي تقوم بها واجهة المستخدم، عبر المرضى، والجدول الزمني، والاستدعاءات، والميزانيات، والمدفوعات، والتقارير.

- **يفعل ولا يكتفي بالإجابة.** يقوم الوكيل بتشغيل أدوات حقيقية — البحث عن المرضى، حجز المواعيد أو إعادة جدولتها، تسجيل دفعة مالية، سحب تحصيلات هذا الشهر — ويربطها ببعضها لإكمال المهمة من البداية إلى النهاية.
- **لا يمكنه أبداً تجاوز صلاحياتك.** يتم إعادة التحقق من كل استدعاء للأدوات مقابل صلاحيات المستخدم (RBAC permissions) عند نقطة التنفيذ. يمكن للمساعد رؤية والقيام بـ *ما يمكن* لهذا المستخدم القيام به بالضبط من خلال واجهة المستخدم — ليس أكثر من ذلك، وضمن نطاق عيادته.
- **بياناتك محمية.** يتم حجب معلومات المرضى الشخصية (PHI) قبل إرسال أي شيء إلى موفر الخدمة السحابية للذكاء الاصطناعي: يتم استبدال أسماء المرضى وهواتفهم ورسائل البريد الإلكتروني والمعرفات الخاصة بهم برموز مميزة حتمية (deterministic tokens)، ويتم استبعاد الأدوات السريرية ذات النص الحر تماماً من المسار السحابي. التشفير والحجب مفعل افتراضياً.
- **عمليات الكتابة تتطلب موافقة أولاً.** أي إجراء يغير البيانات (الحجز، المدفوعات، التعديلات) يتوقف مؤقتاً في منتصف المحادثة لطلب تأكيدك الصريح قبل تشغيله.
- **سير عمل موجه.** قوالب جاهزة للمهام — *الملخص اليومي*، *التحضير لزيارة*، *ملء فراغ في الجدول*، *الاستدعاءات المستحقة*، *الميزانيات المعلقة* — تبدأ مهاماً مشتركة متعددة الخطوات بنقرة واحدة.
- **ملخصات استباقية.** اشترك لتلقي ملخص صباحي حتمي يتم إرساله بالبريد الإلكتروني إلى فريقك، يلخص جدول اليوم، والاستدعاءات المستحقة، والميزانيات المفتوحة — دون استخدام نماذج اللغة الكبيرة (LLM) ودون خروج معلومات المرضى الشخصية خارج الموقع.
- **معياري بالتصميم.** يستهلك المساعد الأدوات المنشورة بواسطة كل وحدة (module) من خلال سجل مشترك؛ تساهم كل وحدة بإمكانياتها الخاصة، لذا ينمو المساعد تلقائياً عند تثبيت وحدات جديدة.

المنصة غير مرتبطة بموفر خدمة ذكاء اصطناعي محدد تحت الغطاء (تجريد موفري نماذج اللغة)، مع إمكانية تكوين الموفر، النموذج، وميزانيات الرموز (token budgets) لكل عيادة عند النشر. البنية البرمجية: [docs/technical/copilot-agentic-architecture.md](docs/technical/copilot-agentic-architecture.md).

## التثبيت

صور جاهزة للتشغيل مباشرة (Prebuilt images)، دون الحاجة للاستنساخ أو البناء. على أي خادم يحتوي على Docker:

```bash
curl -O https://raw.githubusercontent.com/dentalpin/dentalpin/main/docker-compose.prod.yml
curl -O https://raw.githubusercontent.com/dentalpin/dentalpin/main/Caddyfile
curl -o .env https://raw.githubusercontent.com/dentalpin/dentalpin/main/.env.prod.example

# قم بتعيين PUBLIC_URL و POSTGRES_PASSWORD و SECRET_KEY في ملف .env ثم:
docker compose -f docker-compose.prod.yml up -d
```

قم بتوجيه النطاق (Domain) إلى الخادم، واضبط `PUBLIC_URL=https://your-domain`، وسيتم توفير شهادة TLS تلقائياً عند أول تشغيل — يقوم Caddy بتمثيل كلا الخدمتين على أصل واحد، لذا لا توجد مشاكل CORS ولا توجد شهادة لتجديدها يدوياً. اضبط `SEED_ON_STARTUP=1` لتحميل بيانات العيادة التجريبية وتصفحها قبل بدء العمل الفعلي.

الصور (Images): [`dentalpin-backend`](https://github.com/dentalpin/dentalpin/pkgs/container/dentalpin-backend) · [`dentalpin-frontend`](https://github.com/dentalpin/dentalpin/pkgs/container/dentalpin-frontend)

## البدء السريع (للتطوير)

البناء من المصدر مع التحديث الفوري (hot reload):

```bash
# تشغيل الخدمات
docker-compose up -d

# تهيئة البيانات التجريبية (باللغة الإنجليزية افتراضياً)

./scripts/seed-demo.sh --lang es

# عيادة تجريبية بنظام ضريبة السلع والخدمات في الهند (واجهة تاملية، أو واجهة إنجليزية مع --country in)
./scripts/seed-demo.sh --lang ta
```

افتح http://localhost:3000

## الميزات

### مساعد الذكاء الاصطناعي (AI Copilot)
- **مساعد تفاعلي (Agentic)** — وكيل محادثة يخطط وينفذ مهاماً متعددة الخطوات عبر المرضى، والجدول الزمني، والاستدعاءات، والميزانيات، والمدفوعات، والتقارير عن طريق استدعاء عمليات حقيقية.
- **توافق الصلاحيات (RBAC)** — تتم إعادة التحقق من كل إجراء مقابل صلاحيات المستخدم؛ يمكن للوكيل فقط القيام بما يمكن لهذا المستخدم القيام به من خلال واجهة المستخدم، وضمن نطاق عيادته.
- **حجب معلومات المرضى (PHI)** — يتم تحويل معرفات المرضى إلى رموز مميزة قبل إرسالها إلى نموذج اللغة الكبيرة؛ وتبقى البيانات السريرية النصية خارج المسار السحابي. مفعل بشكل افتراضي.
- **تأكيد عمليات الكتابة** — تتوقف الإجراءات التي تعدل البيانات مؤقتاً لطلب تأكيد المستخدم الصريح في منتصف المحادثة.
- **مهام مجهزة وملخصات** — مهام بنقرة واحدة (ملخص صباحي، تحضير لزيارة، ملء موعد شاغر) بالإضافة إلى ملخص صباحي دوري اختياري عبر البريد الإلكتروني.
- **متعدد اللغات ومستقل عن موفر الخدمة** — يتحدث إليك بلغة واجهة المستخدم الخاصة بك؛ موفر خدمة الذكاء الاصطناعي والنموذج وميزانية الرموز قابلة للتهيئة لكل عيادة.

### الإدارة السريرية
- **سجلات المرضى** — ملفات تعريف كاملة للمرضى تحتوي على البيانات الشخصية، ومعلومات الاتصال، والتاريخ الطبي، والملاحظات.
- **مخطط الأسنان (Odontogram)** — رسم بياني تفاعلي للأسنان مع تتبع العلاج لكل سن أو سطح.
- **تقويم المواعيد** — عروض أسبوعية ويومية مع إمكانية السحب والإفلات، وأعمدة احترافية، واكتشاف التعارضات.
- **كتالوج العلاجات** — كتالوج قابل للتخصيص يحتوي على الرموز والأسعار وأنواع ضريبة القيمة المضافة والفئات.

### الإدارة المالية
- **الميزانيات والتقديرات** — إنشاء ميزانيات العلاج، وتتبع سير عمل الموافقة (مسودة ← معلق ← مقبول/مرفوض)، وتوقيع المريض، وإنشاء ملفات PDF.
- **الفواتير** — إنشاء فواتير من الميزانيات أو فواتير مستقلة، وترقيم تلقائي، وطرق دفع متعددة، وتصدير PDF.
- **المدفوعات** — تتبع الدفعات الجزئية، وسجل المدفوعات، وحساب الرصيد المتبقي.

### إدارة العيادة
- **صلاحيات الوصول القائمة على الأدوار** — خمسة أدوار (مدير، طبيب أسنان، أخصائي صحة، مساعد، موظف استقبال) بصلاحيات دقيقة.
- **إدارة الغرف/العيادات** — تحديد غرف العلاج مع الجداول الزمنية والألوان الخاصة بها.
- **إدارة المهنيين** — تعيين المواعيد لأطباء أسنان أو أخصائيين محددين.

### تجربة المستخدم
- **محددات بصرية ذكية** — قوائم منسدلة ذكية تعرض المرضى الأخيرين والعلاجات الشائعة.
- **واجهة تسع لغات** — الإنجليزية، الإسبانية، الفرنسية، البرتغالية، التاميلية، الألمانية، الهنغارية، البولندية، والإيطالية — للتطبيق الأساسي وجميع الوحدات.
- **الوضع الداكن** — تبديل المظهر بناءً على إعدادات النظام.
- **تصميم متجاوب** — يعمل على الحواسيب المكتبية والأجهزة اللوحية.

### الميزات التقنية
- **بنية معيارية (Modular)** — نظام قائم على المكونات الإضافية لسهولة التوسيع.
- **ناقل الأحداث (Event Bus)** — اتصالات بين الوحدات للإشعارات والتكاملات.
- **واجهة برمجية REST API** — واجهة برمجة تطبيقات كاملة مع وثائق OpenAPI المدمجة.
- **تحديثات في الوقت الفعلي** — واجهة مستخدم تفاعلية مع تحديثات متفائلة (optimistic updates).

## اللغات

تأتي واجهة المستخدم متوفرة بـ **تسع لغات** — الإنجليزية، الإسبانية، الفرنسية، البرتغالية، التاميلية (தமிழ்)، الألمانية، الهنغارية، البولندية والإيطالية — تغطي التطبيق الأساسي **وجميع طبقات الوحدات**، مع اختبار مطابقة المفاتيح المفروض في نظام التكامل المستمر (CI) لمنع أي انحراف في الترجمات. تستخدم اللغة البولندية قواعد الجمع الكاملة ثلاثية الصيغ.

اتصالات المرضى (قوالب البريد الإلكتروني، ملفات PDF) تصدر حالياً بـ **خمس لغات** (الإسبانية، الإنجليزية، الفرنسية، البرتغالية، التاميلية)؛ حيث تختار كل عيادة لغة التواصل الخاصة بها بشكل مستقل عن لغة واجهة المستخدم الخاصة بالموظفين.

هل تريد إضافة لغتك؟ إضافة لغة جديدة هي مساهمة تقتصر على الترجمة فقط — راجع [مشكلات i18n](https://github.com/dentalpin/dentalpin/issues?q=label%3Ai18n) أو افتح تذكرة جديدة.

## التطوير

### المتطلبات الأساسية

- Docker و Docker Compose (4 جيجابايت من الذاكرة العشوائية كافية لبيئة التطوير؛ بناء نسخة الإنتاج للواجهة الأمامية من `Dockerfile.prod` يتطلب أكثر من 6 جيجابايت — راجع ملاحظة `NODE_OPTIONS` هناك).
- Python 3.11+ (لتطوير الخلفية محلياً).
- Node.js 18+ (لتطوير الواجهة الأمامية محلياً).

### التشغيل محلياً

```bash
# تشغيل جميع الخدمات
docker-compose up

# أو تشغيل الخلفية بشكل منفصل
cd backend
pip install -e ".[dev]"
uvicorn app.main:app --reload

# أو تشغيل الواجهة الأمامية بشكل منفصل
cd frontend
npm install
npm run dev
```

### إدارة قاعدة البيانات

```bash
# إعادة تعيين قاعدة البيانات وتشغيل الهجرات (migrations)
./scripts/reset-db.sh

# تهيئة البيانات التجريبية (باللغة الإنجليزية افتراضياً)
./scripts/seed-demo.sh

# تهيئة البيانات التجريبية (باللغة الإسبانية)
./scripts/seed-demo.sh --lang es

# الإعداد الكامل (إعادة تعيين + تهيئة البيانات بأمر واحد)
./scripts/setup-demo.sh
```

### تشغيل الاختبارات

```bash
# اختبارات الوحدة والتكامل للخلفية (داخل Docker)
docker-compose exec backend python -m pytest -v

# اختبارات Alembic البطيئة (اختيارية، راجع docs/technical/creating-modules.md)
docker-compose exec backend python -m pytest -v -m alembic_roundtrip

# اختبارات الوحدة للواجهة الأمامية (vitest)
cd frontend
npm run test
```

**اختبارات المتصفح الشاملة (Playwright E2E)** متواجدة في `frontend/tests/e2e/` وتعمل على كامل البيئة في `localhost:3000` ← `:8000`. تعمل على الجهاز المضيف لأن حاوية واجهة المستخدم Alpine لا يمكنها تشغيل متصفح Chromium.

```bash
# الإعداد لمرة واحدة
(cd frontend && npm install && npx playwright install chromium)

# تأكد من تشغيل البيئة بالكامل وتهيئتها بالبيانات أولاً
docker-compose up -d
./scripts/seed-demo.sh

# اختبارات E2E الكاملة (التنقل + الصلاحيات + فحص تفاصيل المريض)
./scripts/e2e.sh

# اختبار ملف واحد
./scripts/e2e.sh rbac

# الواجهة التفاعلية للأداة
./scripts/e2e.sh --ui
```

مرجع دليل التشغيل الكامل وبيانات الاختبار: [docs/technical/e2e-testing.md](docs/technical/e2e-testing.md).

## البنية البرمجية

يستخدم DentalPin بنية برمجية معيارية قائمة على المكونات الإضافية. كل ميزة عبارة عن وحدة قائمة بذاتها تقوم بما يلي:
- تعريف نماذج SQLAlchemy الخاصة بها.
- توفير مسارات FastAPI.
- إمكانية الاشتراك في الأحداث من الوحدات الأخرى.

راجع [ADR 0001 — modular plugin architecture](docs/adr/0001-modular-plugin-architecture.md) و [docs/technical/creating-modules.md](docs/technical/creating-modules.md) لمزيد من التفاصيل.
