# Пакетное создание и проверка плана лечения

## Клинический поток

1. Сотрудник выбирает пациента и ответственного врача.
2. Для каждой строки выбирает процедуру из каталога с привязкой к одонтограмме, указывает один или несколько зубов и, при необходимости, поверхности.
3. Программа создаёт план в статусе `draft` и сохраняет все строки за один запрос.
4. Врач проверяет диагнозы, распределение по зубам и рассчитанную по снимкам цен общую смету на странице плана.
5. Врач запускает существующее действие подтверждения. Оно переводит план в `pending` и создаёт черновик сметы для последующего согласования с пациентом.
6. Подтверждённые пункты связываются с визитами по существующему сценарию записи; выполнение визита обновляет связанные пункты плана.

Пакетное создание не отправляет смету пациенту и не подтверждает план. Врач может исправить план до его подтверждения. Если хотя бы одна строка не проходит проверку, план и созданные для него лечения откатываются целиком.

## Правила валидации

- В пакете должно быть от 1 до 100 строк.
- Каждая строка ссылается ровно на одну существующую процедуру или создаёт новое лечение по процедуре каталога.
- Новое лечение создаётся для того же пациента и клиники, что и план.
- Номера зубов и поверхности проверяются существующей схемой одонтограммы.
- Одна и та же запись лечения не может повторяться в пакете или уже входить в другой пункт плана.
- Порядок строк фиксируется порядком в запросе.
- Назначенный врач должен быть действующим клиническим участником той же клиники.
- Цена рассчитывается сервером из снимка лечения/каталога; клиентские суммы не являются источником истины.

## API

`POST /api/v1/treatment_plan/treatment-plans/batch`

```json
{
  "plan": {
    "patient_id": "<uuid>",
    "title": "Первичный план",
    "assigned_professional_id": "<uuid>"
  },
  "items": [
    {
      "create_treatment": {
        "catalog_item_id": "<uuid>",
        "tooth_numbers": [14, 15],
        "surfaces": ["M", "O"]
      }
    }
  ]
}
```

Ответ содержит созданный план и вложенные пункты с фактическими ценами и зубами. Требуется право `treatment_plan.plans.write`. Подтверждение и создание сметы остаются отдельными операциями `POST /treatment-plans/{id}/confirm`.
