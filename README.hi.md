## DentalPin क्यों?

दुनिया भर के डेंटल क्लिनिकों की बुनियादी ज़रूरतें एक जैसी हैं: मरीज़ों का प्रबंधन, अपॉइंटमेंट तय करना, उपचारों पर नज़र रखना और प्रैक्टिस को कुशलता से चलाना। फिर भी सॉफ़्टवेयर बाज़ार दर्जनों स्थानीय, बंद-स्रोत समाधानों में बँटा है, जो क्लिनिकों को महँगे अनुबंधों और पुरानी तकनीक में बाँध देते हैं।

**हमारा मानना है कि अब बदलाव का समय है।**

DentalPin एक सरल विचार पर बना है: **हर जगह के डेंटल क्लिनिकों के लिए एक खुला प्लेटफ़ॉर्म।** कोई और क्षेत्रीय समाधान नहीं, बल्कि एक वैश्विक आधार जिसे कोई भी क्लिनिक अपना सके, कोई भी डेवलपर आगे बढ़ा सके और कोई भी समुदाय अपनी भाषा में ढाल सके।

### अभी क्यों?

AI ने बदल दिया है कि छोटी टीमें क्या बना सकती हैं। जिन सुविधाओं के लिए कभी बड़े विकास विभाग चाहिए होते थे, वे अब कुछ ही दिनों में बन सकती हैं। यही वह अवसर है जब हम वह सोर्स-उपलब्ध डेंटल सॉफ़्टवेयर (BSL 1.1, प्रकाशन के चार वर्ष बाद Apache 2.0) बना सकते हैं जो वर्षों पहले होना चाहिए था — इससे पहले कि क्लिनिक ऐसे पुराने सिस्टम में फँस जाएँ जिनसे निकलना मुश्किल हो।

### हमारे सिद्धांत

- **सोर्स-उपलब्ध (BSL 1.1)** — आपके क्लिनिक का डेटा आपका है। आपका सॉफ़्टवेयर भी आपका होना चाहिए।
- **मॉड्यूलर** — सरल शुरुआत करें, ज़रूरत के अनुसार जोड़ें। जिन सुविधाओं का कभी उपयोग नहीं करेंगे, उनका भुगतान न करें।
- **वैश्विक डिज़ाइन** — पहले दिन से स्थानीयकरण के लिए बना। वही कोर, कोई भी भाषा, कोई भी देश।
- **API-फ़र्स्ट** — हर सुविधा एक API है। किसी भी चीज़ से जोड़ें, सब कुछ स्वचालित करें।
- **AI-तैयार** — AI युग के लिए संरचित। बुद्धिमान शेड्यूलिंग, नैदानिक निर्णय सहायता और कार्य-प्रवाह स्वचालन के लिए तैयार।

### दृष्टि

हम केवल सॉफ़्टवेयर नहीं बना रहे — हम एक पारिस्थितिकी तंत्र की नींव बना रहे हैं। एक ऐसा प्लेटफ़ॉर्म जहाँ डेवलपर मॉड्यूल का योगदान दें, क्लिनिक सुधार साझा करें और पूरा दंत समुदाय सामूहिक नवाचार से लाभ उठाए।

क्लिनिक पिछले दशक के बंद, महँगे सॉफ़्टवेयर से बेहतर के हक़दार हैं। DentalPin खुला विकल्प है।

## ✨ AI कोपायलट

DentalPin के साथ एक अंतर्निहित **एजेंटिक AI सहायक** आता है, जिससे आप पूरे क्लिनिक से बस बात कर सकते हैं। उससे किसी मरीज़ को खोजने, कोई स्लॉट खाली करने, बिना उत्तर वाले उपचार अनुमान का फ़ॉलो-अप करने या दिन का सारांश देने को कहें — सरल भाषा में — और वह आपके वास्तविक डेटा पर काम करता है।

![AI कोपायलट](docs/screenshots/ia.png)

यह ऊपर से जोड़ा गया कोई चैटबॉट नहीं है। कोपायलट एक सच्चा एजेंट है जो **कई चरणों वाले कार्यों की योजना बनाकर उन्हें पूरा करता है**, उन्हीं कार्रवाइयों को कॉल करके जिन्हें इंटरफ़ेस करता है — मरीज़, शेड्यूल, रिकॉल, उपचार अनुमान, भुगतान और रिपोर्ट में।

- **यह केवल उत्तर नहीं देता, काम करता है।** एजेंट वास्तविक टूल चलाता है — मरीज़ खोजना, अपॉइंटमेंट बुक करना या बदलना, भुगतान दर्ज करना, इस महीने की वसूली निकालना — और किसी कार्य को शुरू से अंत तक पूरा करने के लिए उन्हें जोड़ता है।
- **यह कभी आपकी भूमिका से आगे नहीं जा सकता।** हर टूल कॉल को निष्पादन के समय उपयोगकर्ता की RBAC अनुमतियों से दोबारा जाँचा जाता है। कोपायलट *ठीक वही* देख और कर सकता है जो वह उपयोगकर्ता इंटरफ़ेस से कर सकता है — उससे अधिक नहीं, और केवल उनके क्लिनिक तक सीमित।
- **आपका डेटा सुरक्षित है।** LLM प्रदाता तक कुछ भी जाने से पहले PHI हटा दिया जाता है: मरीज़ों के नाम, फ़ोन, ईमेल और ID नियत टोकन से बदल दिए जाते हैं, और मुक्त-पाठ नैदानिक टूल क्लाउड मार्ग से पूरी तरह बाहर रखे जाते हैं। रिडैक्शन डिफ़ॉल्ट रूप से चालू है।
- **बदलाव से पहले पूछता है।** डेटा बदलने वाली हर कार्रवाई (बुकिंग, भुगतान, संपादन) चलने से पहले बातचीत के बीच आपकी स्पष्ट पुष्टि के लिए रुकती है।
- **निर्देशित कार्य-प्रवाह।** तैयार प्लेबुक — *दैनिक सारांश*, *विज़िट की तैयारी*, *खाली स्लॉट भरें*, *देय रिकॉल*, *बिना उत्तर वाले उपचार अनुमान* — आम बहु-चरणीय काम एक टैप में शुरू करते हैं।
- **सक्रिय सारांश।** अपनी टीम को ईमेल होने वाला एक नियत सुबह का सारांश चुनें, जिसमें दिन का शेड्यूल, देय रिकॉल और खुले उपचार अनुमान हों — कोई LLM नहीं, कोई PHI बाहर नहीं।
- **डिज़ाइन से मॉड्यूलर।** कोपायलट एक साझा रजिस्ट्री के माध्यम से हर मॉड्यूल द्वारा प्रकाशित टूल का उपयोग करता है; हर मॉड्यूल अपनी क्षमताएँ जोड़ता है, इसलिए नए मॉड्यूल इंस्टॉल होने पर एजेंट अपने-आप बढ़ता है।

अंदर से विक्रेता-निरपेक्ष (LLM-प्रदाता अमूर्तता), जिसमें प्रदाता, मॉडल और प्रति-क्लिनिक टोकन बजट हर डिप्लॉयमेंट में कॉन्फ़िगर किए जा सकते हैं। आर्किटेक्चर: [docs/technical/copilot-agentic-architecture.md](docs/technical/copilot-agentic-architecture.md)।

## इंस्टॉल

पहले से बनी इमेज, न क्लोन, न बिल्ड। Docker वाले किसी भी सर्वर पर:

```bash
curl -O https://raw.githubusercontent.com/dentalpin/dentalpin/main/docker-compose.prod.yml
curl -O https://raw.githubusercontent.com/dentalpin/dentalpin/main/Caddyfile
curl -o .env https://raw.githubusercontent.com/dentalpin/dentalpin/main/.env.prod.example

# .env में PUBLIC_URL, POSTGRES_PASSWORD और SECRET_KEY सेट करें, फिर:
docker compose -f docker-compose.prod.yml up -d
```

किसी डोमेन को सर्वर की ओर इंगित करें, `PUBLIC_URL=https://your-domain` सेट करें, और पहली
बार चालू होने पर TLS अपने-आप मिल जाता है — Caddy दोनों सेवाओं को एक ही origin पर रखता है,
इसलिए न CORS की समस्या है और न ही कोई प्रमाणपत्र नवीनीकृत करना पड़ता है। लाइव होने से पहले
डेमो क्लिनिक लोड करके देखने के लिए `SEED_ON_STARTUP=1` सेट करें।

इमेज: [`dentalpin-backend`](https://github.com/dentalpin/dentalpin/pkgs/container/dentalpin-backend) ·
[`dentalpin-frontend`](https://github.com/dentalpin/dentalpin/pkgs/container/dentalpin-frontend)

## सुविधाएँ

### AI कोपायलट
- **एजेंटिक सहायक** — बातचीत करने वाला एजेंट जो वास्तविक कार्रवाइयों को कॉल करके मरीज़, शेड्यूल, रिकॉल, उपचार अनुमान, भुगतान और रिपोर्ट में बहु-चरणीय कार्यों की योजना बनाकर उन्हें पूरा करता है
- **RBAC समानता** — हर कार्रवाई उपयोगकर्ता की अनुमतियों से दोबारा जाँची जाती है; एजेंट केवल वही कर सकता है जो वह उपयोगकर्ता इंटरफ़ेस से कर सकता है, और केवल उनके क्लिनिक तक सीमित
- **PHI रिडैक्शन** — LLM तक पहुँचने से पहले मरीज़ पहचानकर्ता टोकन में बदले जाते हैं; मुक्त-पाठ नैदानिक डेटा क्लाउड मार्ग से बाहर रहता है। डिफ़ॉल्ट रूप से चालू
- **पुष्टि के साथ बदलाव** — डेटा बदलने वाली कार्रवाइयाँ बातचीत के बीच उपयोगकर्ता की स्पष्ट पुष्टि के लिए रुकती हैं
- **कार्य-प्रवाह और सारांश** — एक टैप वाली प्लेबुक (दैनिक सारांश, विज़िट की तैयारी, खाली स्लॉट भरें) और वैकल्पिक सुबह का ईमेल सारांश
- **बहुभाषी और विक्रेता-निरपेक्ष** — आपके इंटरफ़ेस की भाषा में बात करता है; LLM प्रदाता, मॉडल और प्रति-क्लिनिक टोकन बजट कॉन्फ़िगर करने योग्य

### नैदानिक प्रबंधन
- **मरीज़ रिकॉर्ड** — व्यक्तिगत डेटा, संपर्क जानकारी, चिकित्सा इतिहास और टिप्पणियों सहित पूर्ण मरीज़ प्रोफ़ाइल
- **दंत चार्ट (ओडोंटोग्राम)** — हर दाँत/सतह पर उपचार ट्रैकिंग वाला इंटरैक्टिव दाँत आरेख
- **अपॉइंटमेंट कैलेंडर** — ड्रैग और ड्रॉप, चिकित्सक कॉलम और टकराव पहचान के साथ साप्ताहिक और दैनिक दृश्य
- **उपचार कैटलॉग** — कोड, मूल्य, कर प्रकार और श्रेणियों वाला अनुकूलन योग्य कैटलॉग

### वित्तीय प्रबंधन
- **उपचार अनुमान** — उपचार अनुमान बनाएँ, स्वीकृति प्रक्रिया ट्रैक करें (मसौदा → लंबित → स्वीकृत/अस्वीकृत), मरीज़ के हस्ताक्षर लें, PDF बनाएँ
- **चालान** — उपचार अनुमान से या स्वतंत्र रूप से चालान बनाएँ, स्वचालित क्रमांकन, कई भुगतान तरीके, PDF निर्यात
- **भुगतान** — आंशिक भुगतान, भुगतान इतिहास और शेष राशि की गणना ट्रैक करें

### प्रैक्टिस प्रबंधन
- **भूमिका-आधारित पहुँच नियंत्रण** — सूक्ष्म अनुमतियों वाली पाँच भूमिकाएँ (व्यवस्थापक, दंत चिकित्सक, हाइजीनिस्ट, सहायक, रिसेप्शनिस्ट)
- **कक्ष प्रबंधन** — शेड्यूल और रंगों के साथ उपचार कक्ष परिभाषित करें
- **चिकित्सक प्रबंधन** — विशिष्ट दंत चिकित्सकों/हाइजीनिस्ट को अपॉइंटमेंट सौंपें

### उपयोगकर्ता अनुभव
- **दृश्य चयनकर्ता** — हाल के मरीज़ और लोकप्रिय उपचार दिखाने वाले स्मार्ट ड्रॉपडाउन
- **ग्यारह भाषाओं का इंटरफ़ेस** — अंग्रेज़ी, स्पेनिश, फ़्रेंच, पुर्तगाली, तमिल, हिन्दी, जर्मन, हंगेरियन, पोलिश, इतालवी और अरबी — कोर ऐप और हर मॉड्यूल
- **डार्क मोड** — सिस्टम के अनुसार थीम बदलना
- **रिस्पॉन्सिव डिज़ाइन** — डेस्कटॉप और टैबलेट पर काम करता है

### तकनीकी सुविधाएँ
- **मॉड्यूलर आर्किटेक्चर** — आसान विस्तार के लिए प्लगइन-आधारित सिस्टम
- **इवेंट बस** — सूचनाओं और एकीकरण के लिए मॉड्यूलों के बीच संचार
- **REST API** — OpenAPI दस्तावेज़ के साथ पूर्ण API
- **रीयल-टाइम अपडेट** — ऑप्टिमिस्टिक अपडेट के साथ रिएक्टिव इंटरफ़ेस

## भाषाएँ

इंटरफ़ेस **ग्यारह भाषाओं** में उपलब्ध है — English, Español, Français, Português,
தமிழ் (तमिल), हिन्दी, Deutsch, Magyar, Polski, Italiano और العربية (अरबी) — जो कोर ऐप **और
हर मॉड्यूल परत** को कवर करती हैं, साथ में CI द्वारा लागू कुंजी-समानता परीक्षण ताकि भाषाएँ
चुपचाप पीछे न छूटें। पोलिश अपने पूरे तीन-रूप बहुवचन नियमों का उपयोग करती है।

मरीज़ों को भेजे जाने वाले संचार (ईमेल टेम्पलेट, PDF) अभी **छह भाषाओं** (es, en, fr, pt, ta, hi)
में बनते हैं; हर क्लिनिक स्टाफ़ इंटरफ़ेस की भाषा से अलग अपनी संचार भाषा चुनता है।

अपनी भाषा चाहिए? नई भाषा जोड़ना केवल अनुवाद का योगदान है — [i18n issues](https://github.com/dentalpin/dentalpin/issues?q=label%3Ai18n)
देखें या नया issue खोलें।

## डेवलपमेंट

### पूर्वापेक्षाएँ

- Docker और Docker Compose (डेव स्टैक के लिए 4GB RAM पर्याप्त है; `Dockerfile.prod` से
  प्रोडक्शन फ़्रंटएंड इमेज बनाने के लिए 6GB+ चाहिए — वहाँ `NODE_OPTIONS` नोट देखें)
- Python 3.11+ (स्थानीय बैकएंड डेवलपमेंट के लिए)
- Node.js 18+ (स्थानीय फ़्रंटएंड डेवलपमेंट के लिए)

### स्थानीय रूप से चलाना

```bash
# सभी सेवाएँ शुरू करें
docker-compose up

# या बैकएंड अलग से चलाएँ
cd backend
pip install -e ".[dev]"
uvicorn app.main:app --reload

# या फ़्रंटएंड अलग से चलाएँ
cd frontend
npm install
npm run dev
```

### डेटाबेस प्रबंधन

```bash
# डेटाबेस रीसेट करें और माइग्रेशन चलाएँ
./scripts/reset-db.sh

# डेमो डेटा भरें (अंग्रेज़ी - डिफ़ॉल्ट)
./scripts/seed-demo.sh

# डेमो डेटा भरें (हिन्दी, नई दिल्ली India GST क्लिनिक)
./scripts/seed-demo.sh --lang hi

# पूर्ण सेटअप (एक कमांड में रीसेट + सीड)
./scripts/setup-demo.sh
```

### परीक्षण चलाना

```bash
# बैकएंड यूनिट + इंटीग्रेशन (Docker में)
docker-compose exec backend python -m pytest -v

# धीमा Alembic राउंड-ट्रिप (वैकल्पिक, docs/technical/creating-modules.md देखें)
docker-compose exec backend python -m pytest -v -m alembic_roundtrip

# फ़्रंटएंड यूनिट (vitest)
cd frontend
npm run test
```

**ब्राउज़र E2E (Playwright)** `frontend/tests/e2e/` में है और `localhost:3000` → `:8000` पर
पूरा स्टैक चलाता है। यह होस्ट पर चलता है क्योंकि Alpine फ़्रंटएंड कंटेनर Chromium नहीं चला सकता।

```bash
# एक बार का सेटअप
(cd frontend && npm install && npx playwright install chromium)

# पहले सुनिश्चित करें कि स्टैक चालू है और डेटा भरा है
docker-compose up -d
./scripts/seed-demo.sh

# पूरा E2E सूट (नेविगेशन + RBAC + मरीज़ विवरण स्मोक)
./scripts/e2e.sh

# एक फ़ाइल
./scripts/e2e.sh rbac

# इंटरैक्टिव UI
./scripts/e2e.sh --ui
```

पूरी रनबुक + फ़िक्स्चर संदर्भ: [docs/technical/e2e-testing.md](docs/technical/e2e-testing.md)।
